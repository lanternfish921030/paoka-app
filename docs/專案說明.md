# 專案說明

## 這個 App 是什麼？

這是一個**台灣田徑運動員專用的管理 App**，用 Kotlin + Jetpack Compose 開發，使用 Firebase 作為後端。

---

## 整體架構

```
底部導覽列（3個頁籤）
├── 首頁
├── 分析
└── 其他
```

---

## 各頁面說明

### 首頁

- 天氣 / AQI / 濕度即時顯示
- 位置卡片 — 用 GPS 定位取得縣市資訊
- 健康數據卡片（接 Health Connect）— 步數、心率、距離、速度、最大攝氧量、HRV 等
- 3 個功能入口：我的賽程、賽事成績查詢、成績紀錄

### 分析頁

- **骨架追蹤**（SkeletonScreen）— 用 MediaPipe 即時偵測關節角度
- **步態分析**（GaitScreen）— 用 YOLO + MediaPipe 偵測觸地期（Initial Contact、Mid Stance、Toe Off）

### 其他頁

- 關於開發者、資料來源、FAQ、條款、聯絡等子頁面

---

## 從首頁進入的功能頁面

| 頁面 | 功能 |
|------|------|
| SearchScreen | **賽事成績查詢** — 列出全台各縣市田徑賽事連結，點進去用 WebView 內嵌顯示成績 |
| ScheduleScreen | **我的賽程** — 新增/編輯/刪除個人賽事排程，整合 Google Calendar 與推播通知 |
| RecordScreen | **成績紀錄** — 顯示個人 PB（最佳成績）、歷年成績，並畫出趨勢折線圖 |

## 技術架構

| 分類 | 技術 |
|------|------|
| 後端 / 認證 | Firebase Auth + Firestore |
| 健康數據 | Health Connect API |
| 姿態辨識 | MediaPipe Pose Landmarker |
| 步態偵測 | YOLO + MediaPipe |
| 成績爬蟲 | Python 後端部署在 Cloud Run（獨立服務） |

| 網路請求 | Retrofit + OkHttp |

## 成績同步流程

```
App (Android)
  │
  │  POST /scores/ctaa/fetch
  │  Authorization: Bearer <Firebase ID Token>
  ▼
Cloud Run (Python 爬蟲)
  │  爬取 CTAA（中華民國田徑協會）成績網站
  │  把結果寫進 Firestore
  ▼
Firestore: scores/{uid}/history/
  │
  │  Snapshot Listener（即時監聽）
  ▼
App 畫面自動更新
```

### 觸發時機

| 時機 | 說明 |
|------|------|
| 進入成績頁自動觸發 | 距上次同步超過 24 小時才呼叫 |
| 手動點「同步」按鈕 | 需先在個人資料填寫真實姓名與協會系統編號（ctaa_id） |

### 呼叫方式

```
POST https://ctaa-svc-134800518696.asia-east1.run.app/scores/ctaa/fetch
Authorization: Bearer <Firebase ID Token>
Body: { "force": true/false }
```

- `force=true`：強制重爬
- `force=false`：Cloud Run 端可能直接用快取回應

### 資料接收

App 不等 Cloud Run 回傳資料，而是在 Firestore 上設即時監聽。Cloud Run 爬完寫進 Firestore 後，App 的 Snapshot Listener 自動觸發更新畫面。**PB 是在 App 端從 history 計算出來的，不是 Cloud Run 算的。**
